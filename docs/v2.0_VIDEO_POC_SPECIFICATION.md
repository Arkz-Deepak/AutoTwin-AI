# AutoTwin-AI v2.0: Factory Video Telemetry & Inspection POC Specification

## 1. Executive Summary

AutoTwin-AI v2.0 advances from static spatial defect detection on 3D chassis joints to **dynamic factory video telemetry and real-time process stability tracking**. 

### The Problem & Industry Context
In structural fabrication (such as the **Crane Gallery Assembly** and **Heavy Girder 516**), verifying process accuracy requires correlating optical video streams against ground-truth physical logs:
1. **Robotic Welding as a Controlled Accuracy Benchmark**: Real-world robotic welding videos (`video_20260908_170143.mp4` and `video_20260908_171604.mp4`) serve as controlled test datasets. The computer vision metrics generated by AutoTwin-AI (**Arc-On Time**, **Duty Cycle**, **Spatter Particle Tracking**, and **Temporal Stability**) are validated directly against internal robot controller logs.
2. **The Final Target is Manual Human Fabrication**: Once the vision engine validates high accuracy on robotic benchmarks, the system deploys to human fabrication workstations (e.g. manual grinding, fitting, and welding in `IMG_3601.MOV`).
3. **Takt Time & Cycle Time Optimization**: Optical activity telemetry maps directly to the 28 fabrication stages in `data/crane_gallery_stages.xlsx`, establishing automated takt compliance (standard takt: 227 minutes).

## 2. Mathematical Formulations

### A. Arc-On Time & Duty Cycle Detection
The welding arc is an intense, high-luminance plasma event exhibiting saturated blue-white values. The arc core mask $\text{Arc}_{\text{mask}}(x, y)$ is extracted across each frame:

$$\text{Arc}_{\text{mask}}(x, y) = [B(x, y) > 240] \land [G(x, y) > 230] \land [R(x, y) > 200]$$

A frame is classified as $\text{Arc}_{\text{active}} = 1$ when the saturated core pixel count exceeds threshold $\tau_{\text{arc}} = 150$:

$$\text{Arc}_{\text{active}} = \begin{cases} 1, & \text{if } \sum_{x,y} \text{Arc}_{\text{mask}}(x,y) > 150 \\ 0, & \text{otherwise} \end{cases}$$

The cumulative **Arc-On Duration** and **Duty Cycle** are calculated over total duration $T_{\text{total}}$:

$$T_{\text{arc}} = \sum_{t=0}^{N} \text{Arc}_{\text{active}}(t) \cdot \Delta t, \quad \text{Duty Cycle (\%)} = \left(\frac{T_{\text{arc}}}{T_{\text{total}}}\right) \times 100$$

### B. Spatter Particle Tracking (OpenCV Contour Geometry)
Sparks flying from the weld pool represent expelled molten metal droplets. Because the intense arc flame would overwhelm contour detection, the arc mask is dilated using an elliptical structuring element $K_{35 \times 35}$ to form an exclusion zone:

$$\text{ExclusionZone} = \text{Dilate}(\text{Arc}_{\text{mask}}, K_{35 \times 35})$$

Candidate sparks are segmented from grayscale luminance $I_{\text{gray}} \ge 220$ outside the exclusion zone:

$$\text{Sparks}_{\text{candidates}} = \text{Thresh}(I_{\text{gray}}, 220) \land \neg \text{ExclusionZone}$$

Individual spark contours $C_i$ are extracted via `cv2.findContours`:
- **Filter**: Area $2 \le \text{Area}(C_i) \le 300\text{ px}$.
- **Spatter Burst Threshold**: A frame is flagged as a *Spatter Burst* when spark count $> 15$ sparks/frame.

### C. Process Stability Index & Temporal Residuals
Process stability measures how smoothly the molten weld pool advances. Temporal Mean Squared Error (MSE) is computed across consecutive downsampled frames ($320 \times 180$):

$$\text{MSE}_t = \frac{1}{H \times W} \sum_{i=1}^H \sum_{j=1}^W |I_t(i, j) - I_{t-1}(i, j)|^2$$

Statistical thresholds are derived from active arc intervals:

$$\text{Threshold}_{3\sigma} = \mu_{\text{MSE}} + 3\sigma_{\text{MSE}}$$

Any frame exceeding $\text{Threshold}_{3\sigma}$ indicates a turbulent arc event, voltage dip, or severe spatter eruption. The **Process Stability Index** is normalized from 0% to 100%:

$$\text{Stability Index (\%)} = \max\left(0, 100 - \frac{N_{\text{instability}}}{N_{\text{arc\_active}}} \times 100 \times 5\right)$$

## 6. Full-Stack Platform Architecture

### FastAPI Backend Endpoints (`backend/main.py`)
- `GET /api/health`: System health and GPU/CPU inference engine readiness.
- `GET /api/v2/stages`: Complete 28-stage fabrication database with cycle times, takt times, and variance.
- `GET /api/v2/telemetry/robotic`: Telemetry reports and plot URLs for robotic benchmark seams.
- `GET /api/v2/telemetry/manual`: Manual fabrication telemetry (active grinding time, spark stream, takt compliance).
- Static Mount `/static/data`: High-resolution telemetry plots and keyframe renders.

### React Dashboard (`frontend/src/App.jsx`)
- **ROBOTIC VIDEO TELEMETRY**: Interactive video switcher (Girder 516 Seams), KPI cards (Arc-On, Spatter Frequency, Stability Index, Controller Sync), and 4-panel telemetry visualization.
- **MANUAL FABRICATION**: Station #7 telemetry, tool engagement tracking, and takt compliance breakdown.
- **CRANE STAGES (28)**: Interactive 28-stage table with section filters (`ALL`, `TAPER PLATE`, `I-BEAM`, `NODE`, `TUBE`, `ASSEMBLY`, `ROBOT`).
- **3D CHASSIS (v1.0)**: Interactive 3D WebGL digital twin with CAD hotspot navigation.

## 7. Roadmap to v3.0: Spatiotemporal ConvLSTM Architecture

Phase 2 will introduce the **Spatiotemporal ConvLSTM 5D Tensor Model** (currently developed and preserved in branch [`feature/v3-convlstm`](https://github.com/Arkz-Deepak/AutoTwin-AI/tree/feature/v3-convlstm)):
- **5D Tensor Input**: $[B, T, C, H, W]$ sliding temporal windows ($T=8$).
- **Recurrent Core**: `ConvLSTMCell` and `ConvLSTM` multi-layer recurrent memory gates that capture spatiotemporal velocity dynamics of the molten pool.
- **Next-Frame Prediction**: Reconstructing frame $t+1$ given frames $t-T+1 \dots t$, with anomaly score defined as prediction error $\text{MSE}(I_{t+1}, \hat{I}_{t+1})$.
